# YouTube 정책 적합성 검토 — 부모 승인 관문

- 검토일: 2026-10-09
- 상태: **내부 검토 완료·YouTube 공식 확인 없음** / 변경안 A 채택, Compliance Audit 미신청 (2026-10-09 사용자 확정)
- 주의: 이 문서는 정책 원문에 대한 내부 해석이다. YouTube가 이 설계를 허용한다고 확인한 것이 아니다.
- 근거 문서 (2026-10-09 확인)
  - YouTube API Services Developer Policies: https://developers.google.com/youtube/terms/developer-policies
  - Developer Policies Guide: https://developers.google.com/youtube/terms/developer-policies-guide
  - Required Minimum Functionality: https://developers.google.com/youtube/terms/required-minimum-functionality

## 1. 결론 요약

| 구분 | 결론 |
| --- | --- |
| 현재 결정 그대로 (미승인 영상을 재생 가능한 것처럼 보여주고, 누르면 재생 대신 승인 요청) | **위반 위험 높음.** 재생 버튼 외 행동을 시청 조건으로 요구하는 III.F.3.b와 정면으로 겹친다. |
| 변경안 (서비스는 승인 채널 영상만 재생 대상으로 제공하고, 미승인 결과는 "채널 추가 요청" 카드로만 표시) | **회색지대이지만 방어 가능.** 재생을 막는 관문이 아니라 서비스가 제공하는 콘텐츠 범위를 정하는 기능 제한(III.C.6)으로 설명할 수 있다. 제한 사유를 안내하는 조건(III.C.7)을 지켜야 한다. |
| 승인 모드 해제 (전체 검색 → 바로 재생) | 문제없음. |
| 서비스 로그인·가족 등록 확인 | 허용. III.F.3.b가 클라이언트의 정상 기능인 로그인·연령 확인을 예외로 명시한다. |

정책 문서와 해설 어디에도 보호자 통제(parental control)나 채널 허용 목록을 직접 다룬 조항은 없다. 그래서 변경안도 "명시적으로 허용됨"이 아니라 "조항 해석상 방어 가능"이다. 최종 확인 수단은 YouTube API Compliance Audit 신청이다(4장).

## 2. 관련 조항과 이 서비스에 대한 해석

### 2.1 재생 관문 — 가장 큰 쟁점

- **III.F.3.b:** 재생 버튼 클릭 외의 행동을 요구해 영상 접근을 막으면 안 된다. 예시는 채널 구독·좋아요 요구다. 단 로그인·연령 확인처럼 클라이언트의 정상 기능에 속하는 것은 허용한다.
- **해설(Guide), "Your API service must reflect a user's standard experience on YouTube":** "Do not" 목록에 "영상 시청 사용자에게 제한을 걸거나 접근을 막는 것"이 있다. 재생 버튼 외에 무언가를 해야 하면 위반일 가능성이 높다고 설명한다.
- **해석:** 영상 카드를 재생 가능한 형태로 보여준 뒤 누르면 "부모 승인 필요"가 뜨는 흐름은 사용자 입장에서 시청 전 추가 행동(승인 대기)을 요구하는 관문이다. 문언상 가장 가까운 금지 사례다.

### 2.2 기능 제한과 안내

- **III.C.6:** 기능 제한이 클라이언트의 핵심 목적이고 필수 최소 기능(RMF) 항목이 아니면 YouTube 기능을 제한할 수 있다. 예시는 프랑스어 학습 앱이 프랑스어 번역만 제공하는 경우다.
- **III.C.7:** 허용된 제한이라도 ① 제한마다 이유를 사용자에게 설명하고, ② YouTube가 건 제한이 아님을 밝히고, ③ 전체 기능에 접근할 방법을 알려야 한다(예: YouTube 측 기능으로 연결).
- **해석:** "부모가 고른 채널만 보는 가족용 페이지"는 제한 자체가 서비스의 핵심 목적이라고 설명할 수 있다. 다만 ③을 문자 그대로 적용하면 "YouTube에서 보기" 같은 경로를 줘야 할 수 있다. 이것이 가족 서비스 목적과 충돌하는 부분이 회색지대의 핵심이다. 내장 플레이어 자체에 YouTube로 가는 링크가 남아 있다는 점은 이 조건을 충족한다는 논거가 될 수 있지만, 확정 해석은 아니다.

### 2.3 사용자 모르게 필터링 금지

- **해설, "Respect user privacy":** 사용자가 모르거나 동의하지 않은 상태에서 콘텐츠 접근을 제한·필터링하면 안 된다.
- **해석:** 부모 설정과 제한 이유를 아이 화면에 항상 보이게 하면 "모르게"에 해당하지 않는다. 이는 III.C.7 안내 요구와도 맞는다.

### 2.4 플레이어 변경 금지 — 기존 결정과 일치

- **III.I.4·III.I.6:** 플레이어 기능·링크를 제거·가림·변경·차단하면 안 된다.
- **RMF:** 플레이어 앞에 오버레이·프레임을 띄우면 안 된다. 플레이어 영역은 200×200px 이상이어야 하고, 보이기 전에 자동 재생하면 안 된다. Referer를 숨기면 안 된다(`noreferrer` 금지).
- **해설:** 썸네일 위 자체 재생 버튼은 허용하지만 누르면 재생이 시작되어야 한다. 영상 종료 후 관련 영상 링크를 막는 것은 금지다.
- **해석:** `rel=0` 사용, 관련 영상 클릭을 가로채지 않기, 플레이어 위 승인 화면 금지 등 기존 결정과 일치한다. 추가로 **재생 버튼처럼 보이는 썸네일은 반드시 재생을 시작해야 한다.** 따라서 미승인 영상 카드는 재생 버튼처럼 보이면 안 된다.

### 2.5 YouTube 대체 서비스 금지

- **III.I.1:** 큰 독립적 가치를 더하지 않고 YouTube 핵심 경험을 복제하면 안 된다.
- **해석:** 홈·쇼츠 피드를 재현하지 않고, 보호자 큐레이션이라는 별도 가치를 더하므로 방어 가능하다. 기존 "홈·쇼츠 피드 미제공" 결정과도 맞는다.

### 2.6 아동 대상 클라이언트

- **III.J:** COPPA·GDPR 등 관련 법상 아동을 대상으로 하는 클라이언트는 다음을 지켜야 한다. Google에 아동 대상임을 통지하고, 맞춤 광고를 쓰지 않고, YouTube 쓰기 동작(업로드·댓글·재생목록 생성·구독 추가 등)을 하지 않는다.
- **III.E.4.j:** 임베드하는 영상마다 Made for Kids 상태를 조회하고, 해당 영상에서는 추적을 꺼야 한다.
- **해석:** 이 서비스는 쓰기 동작과 광고가 없으므로 아동 대상으로 분류되어도 기능상 부담이 작다. 중1 자녀(만 12~13세)가 주 사용자이므로 **아동 대상 기준에 맞춰 보수적으로 설계**하는 것을 권고한다. Google 통지가 필요한지는 공개 범위(가족 전용)와 함께 Compliance Audit에서 확인한다.

### 2.7 데이터 저장 — 신규 요구사항

- **III.E.4.d:** 사용자 인증 없이 받은 API 데이터는 필요한 만큼만, 최대 30일까지 저장할 수 있다. 이후 삭제하거나 새로 받아야 한다. 정책 문서에는 채널 ID·영상 ID를 이 규칙의 예외로 둔다는 문구가 없다.
- **해석:** 승인 채널 목록에 저장하는 채널 이름·썸네일 등 메타데이터와 승인 채널 영상 목록 캐시는 **30일 안에 다시 받아 갱신**해야 한다. 승인 기록 자체(어느 프로필이 어느 채널을 언제 승인했는지)는 서비스 자체 데이터다. 다만 함께 저장하는 YouTube 데이터는 주기적으로 갱신하도록 설계한다.

## 3. 설계 변경안 (A 채택)

### 변경 전 (현재 DECISIONS)
검색 결과 전체 노출 → 아이가 미승인 채널 영상을 선택 → **재생 전에** 부모 승인 요청 → 승인되면 재생.

### 변경안 A — "재생은 승인 채널만, 미승인은 채널 추가 요청" (채택)

- 검색 탭은 전체 검색 결과를 보여준다(기존 유지).
- **승인 채널 영상:** 카드에 재생 표시가 있고, 누르면 즉시 재생한다.
- **미승인 채널 영상:** 카드에 재생 버튼·재생 유도 표시를 두지 않는다. 플레이어도 만들지 않는다. 카드의 동작은 "○○ 채널 추가 요청"이다. 요청한 영상은 부모가 판단하는 참고 정보로 함께 전달한다.
- 아이 화면에 "이 페이지는 부모님이 고른 채널의 영상만 재생해요. YouTube의 제한이 아니라 우리 가족 설정이에요." 같은 안내를 상시 표시한다(III.C.7, 사용자 인지).
- 부모가 승인하면 그 채널의 영상(요청했던 영상 포함)이 재생 대상이 된다.
- 요점: 서비스가 **재생을 제공하는 범위**를 승인 채널로 정하는 것이다. 이미 제공한 재생을 조건부로 막는 구조가 아니다.

### 변경안 B — "검색 자체를 둘로 나누기" (미채택)

- `검색` 탭은 승인 채널 안에서만 영상을 검색한다.
- 별도 `채널 찾기`에서 채널 단위로만 검색하고 추가를 요청한다. 미승인 영상 결과 자체가 나오지 않는다.
- 장점: 관문처럼 보일 여지가 가장 작다.
- 단점: "전체 검색 결과를 본다"는 기존 결정이 바뀐다. 채널별 검색은 호출 수가 늘어 일 할당량 부담이 커진다(`search.list`는 별도 한도로 하루 100회·호출당 1 — 2026-10-09 정정).

### 변경 없음으로 유지되는 것
- 승인 모드 해제 시 전체 검색 → 바로 재생.
- `rel=0`, 플레이어 무변경, 관련 영상 클릭 사전 차단 미약속.
- 승인 단위 = YouTube 채널, 서비스 내부 목록, 실제 구독 미반영.

## 4. 남은 확인 방법

1. **YouTube API Compliance Audit — 신청하지 않기로 결정(2026-10-09):** 해설은 허용 여부가 불확실하면 Audit을 신청하라고 안내한다. 서비스 요약에 "가족 전용, 비공개, 보호자 큐레이션, 아동 사용자 포함"을 명시한다. 가족 전용 비공개 서비스라도 위반으로 판정되면 API 키 회수·할당량 축소가 가능하다는 점이 위험 요인이다.
2. **신청 시점 권고:** 변경안을 확정하고 화면 흐름이 정리된 뒤 신청한다. 화면 캡처나 흐름 설명이 있어야 심사가 구체적이다.
3. **보장할 수 없는 것(재확인):** 변경안을 써도 승인 채널 영상의 플레이어 안 링크로 YouTube 앱·사이트에 들어가는 경로는 막을 수 없다. 기기 차원의 보완(Family Link 등)이 필요하다.

## 5. 이 검토로 새로 생긴 요구사항

- 미승인 영상 카드에 재생 버튼·재생 유도 표시 금지(변경안 A 채택 시).
- 아이 화면에 제한 이유와 "YouTube 제한이 아닌 가족 설정"임을 상시 안내.
- 임베드하는 영상마다 Made for Kids 상태 조회, 해당 영상 추적 비활성.
- 저장한 YouTube 메타데이터·영상 목록 캐시는 30일 안에 갱신하거나 삭제.
- 플레이어 오버레이 금지, 200×200px 이상, 보이기 전 자동 재생 금지, Referer 유지.
