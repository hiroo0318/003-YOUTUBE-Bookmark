## 1. 한 줄 정의와 목표

가족 구성원이 Google 계정으로 로그인해, 아이는 YouTube를 검색하되 **부모가 승인한 채널의 영상만 재생**하고, 부모는 아이의 채널 추가 요청을 승인·거절하는 모바일 우선 웹(PWA).

| 목표 | 비목표 (하지 않음) |
| --- | --- |
| YouTube 홈·쇼츠 피드 노출 없이 검색·시청 | YouTube 홈·추천·쇼츠 피드 재현 |
| 아이별 승인 채널 목록(= 북마크) | 영상 단위 북마크 |
| 채널 추가 요청 → 부모 승인 흐름 | 플레이어 기능·링크·광고 가리기, 다운로드 |
| 웹 푸시 알림 (부모: 요청 도착 / 아이: 승인·거절 결과) | 실제 YouTube 구독 추가, 이메일 알림 |
| 무료 운영(Supabase Free 등) | 가족 외부 공개 서비스 |

## 3. 핵심 상태 규칙

### 3.1 채널 상태 (아이 프로필별) **[확정]**

| 상태 | 의미 | 아이 카드 표시(승인 모드 켜짐) |
| --- | --- | --- |
| `none` 미승인 | 기록 없음 | 재생 표시 없음, `채널 추가 요청` 버튼 |
| `pending` 요청 대기 | 아이가 요청함 | 재생 표시 없음, `부모님 확인 중` |
| `approved` 승인 | 부모 승인 | ▶ 재생 표시, 누르면 바로 재생 |
| `rejected` 거절 | 부모 거절 | 재생 표시 없음, `부모님이 거절한 채널` (요청 불가) |

상태 전이:

```
none ──(아이 요청)──▶ pending ──(부모 승인)──▶ approved ──(부모 승인 취소)──▶ none
                         │
                         └──(부모 거절)──▶ rejected ──(부모 거절 해제)──▶ none
부모는 대기함 밖에서도 none → approved 로 직접 추가할 수 있다. [제안]
```

- 같은 프로필이 `pending` 상태의 채널을 다시 요청하면 새 요청을 만들지 않는다. 계기가 된 영상만 요청에 추가한다. **[제안]**
- 요청 만료는 없다. **[제안]**
- 승인하면 그 채널의 **현재와 앞으로 올라올 영상 모두** 재생할 수 있다. 부모 승인 화면에 이 범위를 문구로 알린다. **[확정]**

### 3.2 승인 모드

- **켜짐(기본)**: 위 표대로 동작한다.
- **꺼짐**: 검색 결과의 모든 영상을 승인 없이 재생한다(거절 채널 포함). 요청 버튼은 숨긴다. **[확정]** 해제 시 바로 시청. 거절 채널 포함 여부는 **[제안]**이다.
- 다시 켜면 기존 승인·거절 목록을 그대로 쓴다. **[제안]**
- 적용 단위: **아이 프로필별 설정 [제안]**. 아이마다 나이가 다를 수 있기 때문이다.

### 3.3 정책상 지켜야 할 표시 규칙 (근거: 01 정책 검토)

- 재생 표시(▶)는 **누르면 반드시 재생되는 카드에만** 붙인다.
- 미승인 카드는 썸네일을 보여줄 수 있다. 다만 재생 버튼처럼 보이는 요소는 두지 않고, 누르면 채널 추가 요청 시트가 열린다.
- 아이 화면 상단에 탭별 한 줄 안내를 표시한다(12px, 배경 없음). **[확정 2026-10-10]**
  | 탭 | 승인 모드 켜짐 | 꺼짐 |
  | --- | --- | --- |
  | 승인 채널 영상 | 부모님이 승인한 채널의 영상만 모아 보여줘요. | (같음) |
  | 검색 | 보고 싶은 영상을 검색하고 부모님께 요청해요. | 지금은 부모님 설정으로 검색한 영상을 바로 볼 수 있어요. |
- 재생 제한이 YouTube가 아닌 가족 설정이라는 설명(정책 III.C.7)은 채널 추가 요청 시트에 둔다: "아직 승인 전이라 볼 수 없어요. YouTube가 아닌 우리 가족 설정이에요." 
- 플레이어 위에 아무것도 덮지 않는다. 화면에 보이기 전에는 자동 재생하지 않는다. 플레이어는 200×200px 이상(권장 16:9, 너비 480px 이상). `rel=0`. Referer를 숨기지 않는다.

## 4. 사용자 여정

### J1. 최초 설정 (부모)
1. 배포 설정에 지정된 이메일로 Google 로그인 → 부모 계정과 가족이 자동으로 생성된다.
2. 가족 관리에서 아이 이메일과 이름(표시명)을 등록한다 → 아이 프로필이 함께 만들어진다.
3. (선택) 다른 보호자 이메일을 부모 권한으로 등록한다.
4. 알림 설정: 홈 화면에 추가 → 알림 허용. iPhone은 iOS 16.4 이상에서 홈 화면 웹앱으로 실행해야 한다.
5. (선택) 아이 승인 채널을 미리 추가한다(검색 → 채널 승인).

### J2. 아이 시청
1. Google 로그인 → 자기 프로필로 바로 진입한다(기본 탭 **[제안]**: 승인 채널 영상).
   - 처음 들어오면 홈 화면 추가·알림 허용 안내를 보여준다(요청 결과를 푸시로 받기 위해). 건너뛸 수 있고 `내 요청` 화면에서 다시 켤 수 있다.
2. `승인 채널 영상` 탭: 최신순 통합 목록과 채널 칩 필터 → 누르면 재생.
   - 탭 안의 검색창으로 **승인 채널 영상만** 검색한다. 서비스에 저장된 목록에서 찾으므로 YouTube 할당량을 쓰지 않는다(6.1).
3. `검색` 탭: 검색어 입력 → **검색 버튼**을 눌러야 실행된다. 결과 카드는 채널 상태에 따라 표시가 다르다.
4. 승인 카드를 누르면 재생 화면으로 간다. 영상이 끝나면 같은 채널의 관련 영상이 표시된다(YouTube 기본 동작).

### J3. 채널 추가 요청 → 승인
1. 아이가 미승인 카드를 누르면 시트가 열린다: 채널 이름·썸네일, "이 채널을 추가해 달라고 부모님께 요청할까요?" → `요청하기`.
2. 카드가 `부모님 확인 중`으로 바뀐다. 아이는 `내 요청` 화면에서 상태를 본다.
3. 부모 기기로 웹 푸시가 온다: "○○이 '△△' 채널 추가를 요청했어요" → 누르면 승인 대기함이 열린다.
4. 부모는 요청 상세에서 채널 정보, 계기 영상(미리보기 가능 **[제안]**), 요청 시각을 본다. 그다음 `승인` 또는 `거절`을 누른다.
   - 승인 확인 문구: "이 채널의 앞으로 올라올 영상도 ○○이 볼 수 있어요."
5. 아이 기기로 웹 푸시가 간다.
   - 승인: "'△△' 채널이 승인됐어요. 지금 볼 수 있어요" → 누르면 **요청할 때 보던 영상(계기 영상)의 재생 화면(KID-03)이 바로 열리고 재생된다. [확정]**
     - 계기 영상이 여러 개면 가장 최근에 요청한 영상을 연다.
     - 모바일 브라우저가 소리 있는 자동 재생을 막으면 재생 화면만 열고, 아이가 ▶ 한 번을 누르면 재생된다.
     - 계기 영상이 삭제됐거나 재생할 수 없으면 그 채널로 거른 승인 채널 영상 탭(KID-01)으로 대신 연다.
   - 거절: "'△△' 채널은 부모님이 허락하지 않았어요" → 누르면 `내 요청`이 열린다.
6. 아이 화면의 카드 상태가 바뀐다. 앱을 열거나 화면으로 돌아오면 다시 조회해 반영한다. 화면을 연 채로 즉시 반영되는 실시간 갱신은 후속이다.

### J4. 승인 관리 (부모)
- 아이별 `승인 채널` 목록에서 승인을 취소하면 `none`이 된다.
- 아이별 `거절 채널` 목록에서 거절을 해제하면 `none`이 된다.
- 승인 모드를 켜고 끌 수 있다(아이별).

### J5. 예외
| 상황 | 처리 |
| --- | --- |
| 미등록 Google 계정 로그인 | "가족으로 등록된 계정이 아니에요" 화면과 로그아웃 버튼. 데이터는 일절 조회하지 않는다. |
| 등록됐지만 아이 프로필이 연결되지 않은 아이 계정 | "부모님께 프로필 연결을 요청하세요" |
| 영상 재생 불가(임베드 금지·지역 제한·삭제) | 플레이어 오류 이벤트를 받아 "이 영상은 여기서 재생할 수 없어요" 안내와 목록 복귀 |
| 검색 할당량 초과 | "오늘 검색 횟수를 다 썼어요. 승인 채널 영상은 계속 볼 수 있어요" |
| 웹 푸시 미지원·미허용 (부모) | 요청은 대기함에 남는다. 부모 홈 화면에 대기 건수 배지 표시 |
| 웹 푸시 미지원·미허용 (아이) | 결과는 `내 요청`에 남는다. 아이 하단 탭 `내 요청`에 새 결과 배지 표시 |
| 승인 대기 중 부모가 그 채널을 직접 승인 | 대기 요청을 자동으로 승인 처리 |
| Supabase 무료 프로젝트 일시 중지 | 운영 메모로 재개 절차를 둔다(서비스 화면 대응 없음) |

## 6. YouTube 연동

할당량 구조(2026-10-09 공식 문서 확인): `search.list`는 **별도 한도로 하루 100회, 호출당 1**이다. 나머지 엔드포인트는 합쳐서 **하루 10,000단위**다. 한도는 태평양 시간 자정에 초기화된다.

| 용도 | API | 비용 | 메모 |
| --- | --- | --- | --- |
| 검색 | `search.list` `type=video`, `videoEmbeddable=true`, `safeSearch=strict`**[제안]**, `maxResults=50` **[확정]** (호출당 1회라 최대치로 받는다) | 검색 한도 1회 | 가족 전체가 하루 100회를 나눠 쓴다(더 보기 포함). 버튼을 누를 때만 호출 |
| 부모 채널 검색 | `search.list` `type=channel`, `maxResults=50` | 검색 한도 1회 | 아이 검색과 같은 하루 100회를 나눠 쓴다 |
| 채널 정보 | `channels.list` `part=snippet,contentDetails` | 1 | `contentDetails.relatedPlaylists.uploads`로 업로드 목록 ID 확보 |
| 승인 채널 영상 | `playlistItems.list` (업로드 목록, `maxResults=50`) | 1단위 | 채널당 최근 50개 **[제안]**. 승인 채널 내 검색의 대상 |
| 승인 채널 더 찾기 | `search.list` `channelId=…`, `type=video` | 검색 한도 1회 | 채널 하나를 골랐을 때만, 버튼으로 실행 **[제안]** |
| 영상 상세 | `videos.list` `part=snippet,status,contentDetails` | 1 (최대 50개 묶음) | `status.madeForKids`, `status.embeddable` 확인 |
| 재생 | IFrame Player API, `rel=0`, `playsinline=1` | — | `onError` 이벤트로 재생 불가 처리 |

- API 키는 서버(Supabase Edge Function)에서만 쓰고 클라이언트에 노출하지 않는다. **[제안]**
- 캐시: 검색 결과 캐시는 짧게(같은 검색어 당일 재사용 **[제안]**). 채널 메타데이터와 영상 목록은 30일 안에 다시 받거나 지운다(정책 III.E.4.d).
- Made for Kids 영상은 추적을 비활성화한다. 이 서비스는 분석·광고 추적을 아예 넣지 않는 것으로 단순화한다. **[제안]**
- `safeSearch=strict`는 보조 수단일 뿐 안전을 보장하지 않는다(기존 결정).

### 6.1 승인 채널 영상 탭의 검색 **[확정: 기능 / 제안: 방식]**

- 대상: 그 아이 프로필의 **승인 채널** 영상 중 재생 가능 판정을 통과한 영상만(6.2).
- 방식: YouTube API를 부르지 않는다. 서비스가 저장한 승인 채널 영상 목록(`yt_video_cache`)의 **제목·채널명**에서 찾는다(설명문 포함 여부는 구현 시 결정).
  - 가족 규모(채널 수십 개 × 50개 = 수천 건)에서는 DB 검색(Postgres `ILIKE`, 필요하면 `pg_trgm`)이나 받아온 목록을 프론트에서 거르는 방식 모두 충분하다. 한국어는 부분 문자열 일치로 처리한다.
  - 입력 중 바로 거르기(즉시 검색)를 허용한다. API 호출이 없으므로 `검색` 탭의 "버튼을 눌러야 검색" 규칙은 이 탭에 적용하지 않는다.
  - 채널 칩을 고른 상태에서 검색하면 그 채널 안에서만 찾는다.
- 한계: 저장된 범위(채널당 최근 50개 **[제안]**) 밖의 옛 영상은 나오지 않는다. 결과가 없으면 "최근 영상에서 찾지 못했어요"라고 안내한다.
- 보조 **[제안]**: 채널 칩을 하나 고른 상태에서만 `YouTube에서 이 채널 더 찾기` 버튼을 보인다. 이 버튼은 그 채널로 한정한 `search.list`를 부르며, 가족 공용 검색 한도(하루 100회)에서 1회를 쓴다. 승인 채널이라 결과는 바로 재생할 수 있다.
- 승인 채널마다 API로 검색하지 않는 이유: 검색 한 번에 승인 채널 수만큼 검색 한도를 쓴다. 예를 들어 승인 채널이 10개면 한 번에 10회를 써서, 하루 10번 검색하면 가족 전체 한도가 끝난다.

### 6.2 승인 채널 영상 목록의 재생 가능 판정 **[제안]**

업로드 목록에는 삭제·비공개·임베드 불가 영상이 섞일 수 있다. 목록에 넣기 전에 판정한다.

- 새로 받은 영상 ID는 `videos.list`(`part=status,contentDetails,snippet`, 50개당 1단위)로 확인한다.
- 다음은 목록과 검색 대상에서 **제외**한다(저장은 하되 `playable=false`).
  - 응답에 없는 영상(삭제)
  - `privacyStatus`가 `private`인 영상
  - `embeddable=false`인 영상
  - `uploadStatus`가 `processed`가 아닌 영상
  - `regionRestriction`으로 한국(KR)에서 막힌 영상
  - 아직 시작하지 않은 실시간 예정 영상
- 판정을 통과했는데도 재생 중 플레이어 오류가 나면 J5 예외대로 안내한다. 그 영상은 `playable=false`로 바꾼다.

### 6.3 승인 채널 영상 저장·갱신 규칙 **[확정 2026-10-10: 누적 방식]**

목록은 **누적**한다. 한 번 들어온 영상은 삭제·비공개·재생 불가가 되거나 승인이 취소되기 전까지 채널 영상 탭에 계속 남는다.

| 시점 | 동작 |
| --- | --- |
| 부모가 채널을 승인한 즉시 | 일반 영상 최신 50개 + 쇼츠 최신 50개를 받아 저장한다(승인 이전의 더 오래된 영상은 넣지 않는다). |
| 아이가 KID-01에 들어올 때 | 응답 뒤에: 마지막 갱신 후 **6시간** 지난 승인 채널의 최신 목록을 받아 **처음 보는 영상만 추가**, 저장 영상 중 **7일** 지난 것 최대 200개 재확인, 30일 넘은 캐시 정리. |
| 아이가 `새 영상 가져오기` 버튼을 누를 때 | 그 프로필의 승인 채널 전체에서 새 영상만 추가(같은 채널은 10분에 한 번). |
| 새 영상 추가 공통 규칙 | 최신 쪽(50개)부터 받아 처음 보는 영상만 추가하고, 한 쪽이 모두 새 영상이면 **저장된 영상을 만날 때까지 다음 쪽을 이어 받는다**(최대 4쪽=200개). 마지막 확인 뒤 50개 넘게 올라와도 빠지지 않는다. |
| 아이가 채널 하나를 고르고 목록 맨 아래 `이전 영상 더 보기`/`이전 쇼츠 더 보기`를 누를 때 | 그 채널·그 종류에서 저장된 영상보다 **오래된 영상 50개**를 더 받는다(약 2단위). 처음 승인 때 기억한 다음 쪽 위치(페이지 토큰)부터 이어 받고, 쪽이 밀려 이미 가진 영상이 나오면 건너뛴다(최대 6쪽). 더 없으면 "이 채널의 영상을 모두 불러왔어요". 받은 영상도 누적·7일 재확인 대상. |
| 매일 1회 정기 실행(Vercel Cron, 04:00 KST) | 모든 승인 채널 새 영상 추가 + 7일 지난 저장 영상 재확인(최대 2,000개) + 30일 넘은 캐시 정리. 앱을 아무도 열지 않아도 누적 목록이 유지된다. |
| 재확인 결과 | `videos.list`로 50개씩 묶어 확인(50개당 1단위). 응답에 없으면(삭제·비공개) 지운다. 요청 계기 영상과 **좋아요한 영상**은 지우지 않고 재생 불가로 표시(좋아요 영상도 7일 재확인 대상이라 30일 정리에 걸리지 않는다). 제목·썸네일·재생 가능 여부는 최신으로 갱신. |
| 30일 동안 재확인되지 못한 캐시 | 삭제한다(정책 III.E.4.d — 사용자 인증 없이 받은 데이터는 최대 30일 보관 후 갱신 또는 삭제, ID 예외 문구 없음). 정상 운영이면 7일 재확인 덕분에 여기까지 오지 않는다. |
| 갱신 실패(할당량·네트워크) | 기존 목록을 유지하고 "마지막 갱신" 시각을 표시한다. |

- 비용 예: 승인 채널 20개·저장 영상 3,000개 → 전체 재확인 60단위. 하루 10,000단위 대비 여유가 크다.
- 승인 채널 영상은 **검색(`search.list`)으로 받지 않는다.** 업로드 목록(`playlistItems.list`)으로 받는다. 검색 한도(하루 100회)는 검색 탭 몫이다.
- 후속 검토: 업로드 일시(`published_at`) 기준으로 오래된 영상을 목록에서 빼는 정책(예: 1년)은 필요해지면 추가한다.
- 배포 때 필요: Vercel 환경변수 `CRON_SECRET`(크론 호출 확인용).

### 6.3-1 영상/쇼츠 구분 **[확정 2026-10-10]**

- YouTube Data API에는 공식 쇼츠 표시가 없다.
- 기본: 채널의 쇼츠 재생목록(`UUSH`+채널ID 뒷부분)과 일반 영상 재생목록(`UULF`+…)을 `playlistItems.list`로 따로 받아 구분한다. **공식 문서에 없는 관행**이라 바뀔 수 있다. 채널 갱신 비용은 1단위 → 2단위(+영상 상세 1~2단위).
- 대체: 재생목록을 못 받으면 전체 업로드 50개를 받고, 3분 이하이면서 세로(`videos.list` `player.embedWidth/Height`)면 쇼츠로 추정한다.
- 저장: `yt_video_cache.is_short`, `is_vertical`. 채널마다 일반 영상 최근 50개 + 쇼츠 최근 50개.

### 6.4 영상 캐시는 채널 단위로 가족이 공유한다 **[확정]**

- 영상 캐시(`yt_channel_cache`, `yt_video_cache`)는 아이 프로필이 아니라 **YouTube 채널 단위**로 한 번만 저장한다. 프로필별 승인 여부는 `channel_states`가 따로 관리한다.
- 같은 채널을 아이 둘이 모두 승인받았다면 그 채널 목록은 한 번만 받아서 함께 쓴다. 갱신 주기 판단(6시간)도 채널 기준이다.
- 아이 화면은 "그 프로필의 `approved` 채널 목록 × 공유 영상 캐시"를 합쳐서 보여준다. 다른 프로필만 승인한 채널의 영상은 캐시에 있어도 보이지 않는다(RLS·조회 조건으로 보장).
- DB에는 링크 주소가 아니라 **영상 ID**와 표시에 필요한 정보(제목·썸네일·게시일·재생 가능 여부)만 저장한다. 시청 링크(`https://www.youtube.com/watch?v=ID`)와 임베드 주소는 ID로 만든다.
- 어느 프로필에서도 승인 상태가 아닌 채널의 캐시는 갱신을 멈추고 삭제한다. 정책상 30일 안에 갱신하지 않은 캐시도 삭제한다.

### 6.5 [후속] 새 영상 푸시 알림(PubSubHubbub)

YouTube 공식 기능으로, 채널에 영상이 올라오거나 제목·설명이 바뀌면 YouTube가 우리 서버에 알려준다.
- 근거: https://developers.google.com/youtube/v3/guides/push_notifications (2026-10-09 확인)

- 방식: 채널이 승인되면 서버가 허브(`https://pubsubhubbub.appspot.com/subscribe`)에 그 채널의 피드(`https://www.youtube.com/xml/feeds/videos.xml?channel_id=CHANNEL_ID`)를 구독한다. 알림(Atom 피드)이 오면 받은 `videoId`를 `videos.list`로 판정(6.2)한 뒤 캐시에 넣는다. 승인이 모두 취소되면 구독을 해지한다.
- 효과: 새 영상이 6시간 주기를 기다리지 않고 거의 바로 목록에 들어온다. 정기 갱신 횟수도 줄일 수 있다.
- 필요 조건: 알림을 받을 공개 콜백 주소(Supabase Edge Function), 구독 확인 요청 처리, 구독 만료 전 재구독.
- 한계: 알림이 빠질 수 있으므로 6.3의 정기·진입 시 갱신은 보조로 유지한다. 공식 문서에는 할당량 소모 여부와 구독 유지 기간이 나와 있지 않아 구현하며 확인해야 한다.
- 도입 시점: 첫 버전에서는 제외한다. 새 영상이 늦게 보여 불편할 때 붙인다.

## 7. 데이터 개요 (Supabase / Postgres)

```
families            id, name, created_at
members             id, family_id, email(unique), role('parent'|'child'), auth_user_id(null until first login), display_name
child_profiles      id, family_id, member_id(unique, 1:1), display_name, approval_mode(bool, default true)
channel_states      profile_id, channel_id, status('approved'|'rejected'), decided_by, decided_at   -- 'none'은 행 없음
channel_requests    id, profile_id, channel_id, status('pending'|'approved'|'rejected'), trigger_video_ids[], created_at, decided_at, decided_by
yt_channel_cache    channel_id, title, thumbnail_url, uploads_playlist_id, fetched_at   -- 채널 단위로 가족 공유, 30일 내 갱신
yt_video_cache      video_id, channel_id, title, thumbnail_url, published_at, made_for_kids, embeddable, playable, fetched_at   -- 링크 대신 ID만 저장
video_likes         profile_id, video_id, created_at   -- 아이 좋아요(채널담 안에서만, YouTube 좋아요와 연결 안 함)
(후속) yt_websub_subscriptions  channel_id, lease_expires_at, status   -- 6.5 새 영상 푸시 알림
push_subscriptions  id, member_id, endpoint, keys, created_at
```

- 최초 부모는 첫 로그인 때 서버에서 `이메일 == 설정값`을 확인한 경우에만 생성한다.
- 로그인한 사용자를 `members.email`로 연결한다(첫 로그인 때 `auth_user_id` 기록). 일치하는 이메일이 없으면 접근 불가 상태가 된다.
- 접근 규칙(RLS): "같은 가족이면 모두 읽기"로 두지 않는다. 테이블별로 아래처럼 나눈다.

| 테이블 | 부모 | 아이 | 서버(Edge Function, service role) |
| --- | --- | --- | --- |
| `families` | 자기 가족 읽기 | 자기 가족 이름만 읽기 | 최초 부모 생성 시 쓰기 |
| `members` | 가족 전체 읽기·등록·권한 변경·삭제 | **자기 행만** 읽기 | 첫 로그인 시 `auth_user_id` 연결 |
| `child_profiles` | 가족 전체 읽기·생성·`approval_mode` 변경 | **자기 프로필만** 읽기(변경 불가) | — |
| `channel_states` | 가족 전체 읽기. 변경은 승인·거절·취소·해제 DB 함수로만 | **자기 프로필 행만** 읽기 | — |
| `channel_requests` | 가족 전체 읽기. 처리는 DB 함수로만 | **자기 프로필 행만** 읽기. 생성은 요청 DB 함수로만(중복 묶기·`rejected` 차단 포함) | — |
| `yt_channel_cache`·`yt_video_cache` | 읽기 | 읽기(자기 승인 채널 범위로 조회) | **쓰기는 서버만** |
| `video_likes` | 가족 아이 것 읽기(1차 화면에는 안 씀) | **자기 프로필 것만** 읽기·추가·삭제. 추가는 승인 채널 영상만(서버 확인) | 재확인 시 읽기 |
| `push_subscriptions` | **자기 구독만** 생성·삭제·읽기 | **자기 구독만** 생성·삭제·읽기 | 발송을 위해 읽기, 만료 구독 삭제 |

  - 푸시 구독(`endpoint`, `keys`)은 같은 가족이어도 다른 구성원이 읽을 수 없다. 발송은 서버만 한다.
  - DB 함수(`security definer`)는 호출자의 역할과 프로필 소유를 함수 안에서 다시 확인한다.
  - YouTube API 키와 service role 키는 서버에만 둔다.
- 승인·거절은 하나의 트랜잭션(DB 함수)으로 처리한다. `channel_requests` 상태 변경과 `channel_states` 반영을 동시에 한다.

## 8. 알림 (웹 푸시)

- PWA(manifest + service worker)와 Web Push(VAPID)를 쓴다. 부모와 아이 모두 같은 앱에서 구독한다.

| 이벤트 | 받는 사람 | 내용 | 누르면 |
| --- | --- | --- | --- |
| 채널 추가 요청 생성 | 그 가족의 부모 전원 | "○○이 '△△' 채널 추가를 요청했어요" | PAR-02 요청 상세 |
| 요청 승인 | 요청한 아이 | "'△△' 채널이 승인됐어요. 지금 볼 수 있어요" | KID-03 계기 영상 바로 재생 (불가 시 KID-01 그 채널로 거름) |
| 요청 거절 | 요청한 아이 | "'△△' 채널은 부모님이 허락하지 않았어요" | KID-05 |

- 부모가 요청 없이 채널을 직접 승인한 경우는 아이에게 알리지 않는다. **[제안]**
- 여러 부모 중 한 명이 처리하면 다른 부모 기기의 대기함에서도 처리됨으로 보인다.
- 푸시 내용에는 요약만 넣고, 승인은 앱 안에서만 처리한다.
- 발송 실패·만료된 구독은 정리한다. 알림을 못 받아도 대기함이 원본이다.
- iPhone·iPad(부모·아이 공통): iOS/iPadOS 16.4 이상이어야 하고, 홈 화면에 추가한 앱에서 알림을 허용해야 한다. 부모는 PAR-05, 아이는 KID-05에서 안내하고 테스트 발송을 제공한다.
- 아이 기기가 Family Link·스크린 타임으로 관리되면 홈 화면 추가나 알림 허용이 막힐 수 있다. 실제 기기로 확인한다(V18).

## 11. 보장할 수 없는 것 (사용자 안내용)

- 승인된 채널 영상의 플레이어 안 링크(YouTube 로고, 종료 후 관련 영상 등)로 YouTube 앱·사이트에 넘어가는 것은 막을 수 없다. 기기 자체 설정(Family Link, 스크린 타임)으로 보완한다.
- 검색 결과에 부적절한 썸네일·제목이 나올 수 있다(`safeSearch=strict`는 보조 수단).
- 승인 채널이 앞으로 올리는 영상의 내용은 서비스가 검사하지 않는다.
- 정책 해석상 방어 가능한 설계일 뿐 YouTube의 공식 승인을 받은 것은 아니다. 정책 위반으로 판정되면 API 키가 제한될 수 있다.

## 12. 구현 전에 정하면 좋은 [제안] 항목 요약

1. 승인 모드를 아이별로 둘지 (제안: 아이별)
2. 승인 모드가 꺼졌을 때 거절 채널도 재생할지 (제안: 재생)
3. 부모가 요청 상세에서 계기 영상을 미리 볼 수 있게 할지 (제안: 가능)
4. 아이 기본 탭 (제안: 승인 채널 영상)
5. 검색에 `safeSearch=strict`를 고정할지 (제안: 고정)
5-2. 부모가 요청 없이 직접 승인한 채널도 아이에게 알릴지 (제안: 알리지 않음)
6. 승인 채널 영상 목록에서 채널당 저장·표시할 최근 영상 수 (제안: 50 — 승인 채널 내 검색 범위이기도 함)
6-1. 승인 채널 내 검색에 설명문도 포함할지, `YouTube에서 이 채널 더 찾기`를 둘지 (제안: 제목·채널명만, 더 찾기 버튼 둠)
7. 기술 스택: Supabase(Auth·DB·Edge Functions) + 프론트 프레임워크·배포처 (미정. 바이브코딩 시작 때 결정)
