# DECISIONS — 가족용 YouTube 북마크 서비스

의미 있는 결정만 기록한다. 미확정 선택지는 `PROJECT_CONTEXT.md`의 열린 질문에 둔다.

## 2026-10-09 — 가족별 별도 페이지를 서비스의 기본 경험으로 둔다

- 결정: Google 로그인과 가족 계정 확인 후 아이 프로필(아이 계정과 1:1 연결, 2026-10-09 확정)로 검색·시청·승인 채널 목록을 사용하는 별도 페이지를 기획 기준으로 둔다.
- 근거: 일반 YouTube 홈과 쇼츠 연속 탐색 목록의 노출을 줄이고 가족별 목록을 제공하려는 사용자 목적.
- 검토 후 채택하지 않은 대안: YouTube 앱 자체의 일반 홈 화면을 기본 진입점으로 사용하는 방식.
- 영향: 가족 계정 확인, 아이 프로필별 데이터 구분, 검색/재생 흐름이 필수 요구사항이 된다.

## 2026-10-09 — 계정 구독 연동은 조건부 후속 기능으로 다룬다

- 결정: 검색·재생·승인 채널 목록을 기본 범위로 삼고, 본인 계정의 구독 목록 조회는 가능성·동의·운영 조건을 확인해 후속 범위로 정한다.
- 근거: 사용자는 구독 연동을 “가능하면” 추가하고 싶다고 표현했다. 본인 구독 목록에는 계정별 OAuth 동의가 필요하다.
- 검토 후 채택하지 않은 대안: 모든 가족 구성원의 YouTube 계정 연결을 첫 버전의 필수 조건으로 삼는 방식.
- 영향: 계정 연결 없이도 기본 서비스 여정을 완성할 수 있어야 한다.

## 2026-10-09 — 자녀 안전을 검색 필터만으로 보장한다고 설명하지 않는다

- 결정: 검색 필터는 보조 수단으로 보고, 자녀에게 보여줄 결과 범위와 보호자 승인 방식은 별도 요구사항으로 결정한다.
- 근거: 공식 검색 필터는 제한 콘텐츠 제외를 시도하며, YouTube 플레이어의 관련 영상과 기본 링크를 완전히 제거할 수 없다.
- 검토 후 채택하지 않은 대안: `safeSearch=strict` 또는 플레이어 옵션만으로 외부 탐색이 차단된다고 가정하는 방식.
- 영향: 자녀 모드의 검색·재생 정책과 기기 차원의 보완 수단이 출시 판단의 핵심이 된다.

## 2026-10-09 — 전체 검색을 열고 시청은 크리에이터 단위로 승인한다

> 일부 변경됨: 미승인 영상 선택 시 "재생 전 승인 요청" 흐름은 아래 "재생은 승인 채널 영상에만 제공한다" 결정으로 대체되었다. 채널 단위 승인·현재·향후 영상 허용 범위는 유지한다.


- 결정: 자녀도 전체 검색 결과를 본다. 승인 단위인 크리에이터는 YouTube 채널로 정의한다. 기본값에서는 미승인 채널의 영상을 선택하면 재생 전에 부모에게 승인을 요청한다. 부모가 승인하면 해당 채널의 현재·향후 영상은 계속 시청할 수 있다.
- 근거: 사용자가 검색은 자유롭게 하되 시청 시 크리에이터를 기준으로 부모가 승인하는 흐름을 지정했다.
- 검토 후 채택하지 않은 대안: 검색 결과 자체를 승인된 크리에이터로 제한하거나, 영상을 하나씩 승인하는 방식.
- 영향: 검색 결과의 승인 상태, 요청 대기·승인·거절 흐름, 크리에이터별 허용 목록, 부모 승인 취소를 요구사항으로 구체화한다. 미래 영상까지 열리는 승인 범위를 부모에게 알려야 한다. **구현 전 YouTube의 재생 관문 정책과 양립하는지 확인해야 한다.**

## 2026-10-09 — 부모는 승인 모드를 해제할 수 있다

- 결정: 부모만 크리에이터 승인 모드를 끌 수 있다. 꺼진 상태에서는 전체 검색 후 재생 가능한 영상을 별도 승인 없이 시청한다.
- 근거: 사용자가 부모의 선택에 따라 전체 검색 → 바로 시청 흐름을 허용하기로 했다.
- 검토 후 채택하지 않은 대안: 승인 모드를 항상 강제하는 방식.
- 영향: 부모 전용 설정 권한과 모드별 재생 동작을 분리해 검증한다.

## 2026-10-09 — 자체 서비스에 YouTube 홈·쇼츠 목록을 제공하지 않는다

- 결정: 자체 페이지는 전체 검색 결과, 아이 프로필별 승인 채널 영상 목록, 선택한 영상 재생을 중심으로 구성한다. YouTube 홈 피드와 쇼츠 연속 탐색 목록은 제공하지 않는다. 영상 종료 후 내장 플레이어의 관련 영상 표시는 허용한다.
- 근거: 사용자가 줄이려는 대상은 홈과 쇼츠 목록을 통한 연속 탐색이라고 명확히 했다.
- 검토 후 채택하지 않은 대안: YouTube 홈·쇼츠 피드를 자체 페이지에 다시 구성하거나, 플레이어의 관련 영상 표시를 제거하려는 방식.
- 영향: 화면 범위가 명확해진다. 검색 결과에 개별 쇼츠 영상이 포함되는지는 별도 확인 사항으로 남긴다.

## 2026-10-09 — 최초 부모 계정이 가족 계정과 권한을 관리한다

- 결정: 사용자 본인의 Google 계정을 최초 부모 계정으로 두고, 이후 부모가 가족 계정을 추가하며 부모/아이 권한을 지정한다. 아이 권한 계정은 허용된 아이 프로필을 선택해 서비스를 이용한다.
- 근거: 사용자가 가족만 이용할 서비스의 계정 관리 방식과 권한 구분을 지정했다.
- 검토 후 채택하지 않은 대안: 누구나 Google 로그인만 하면 가족 데이터에 접근하는 방식, 가족 선택만으로 부모 권한을 얻는 방식.
- 영향: 최초 부모 지정, 등록 계정 확인, 부모/아이 권한 변경, 아이 프로필 접근 범위가 기본 요구사항이 된다.

## 2026-10-09 — 서비스 로그인에 Supabase Google OAuth를 사용한다

- 결정: 가족 구성원의 서비스 로그인에는 Supabase Auth의 Google 로그인을 사용한다. 로그인 후 가족 등록 여부와 권한을 서비스에서 별도로 확인한다.
- 근거: 가족 구성원이 Google 계정으로 접속하는 계획에 적합하고, Supabase는 Google 로그인을 공식 지원한다.
- 검토 후 채택하지 않은 대안: Google 로그인 성공만으로 가족 구성원과 부모/아이 권한을 자동 인정하는 방식.
- 영향: 미등록 계정 차단과 데이터 접근 정책이 필요하다. YouTube 구독 목록 조회에는 서비스 로그인과 별도의 Google 권한 동의가 필요하다.

## 2026-10-09 — 관련 영상은 같은 채널로 좁히되 플레이어 내부 클릭의 사전 승인은 약속하지 않는다

- 결정: 기본 재생에서 YouTube 플레이어의 `rel=0` 옵션을 검토해 종료 후 관련 영상을 같은 채널로 좁힌다. 자체 승인 단위도 YouTube 채널로 맞춘다.
- 근거: YouTube 공식 문서는 `rel=0`에서 관련 영상을 방금 본 영상과 같은 채널에서 표시한다고 설명한다. IFrame Player API는 재생 상태 이벤트를 제공하지만 관련 영상 클릭을 재생 전에 심사하는 수단은 제공하지 않는다.
- 검토 후 채택하지 않은 대안: 플레이어 내부 관련 영상 클릭을 가로채 승인 화면을 띄우거나, 관련 영상 링크를 가리는 방식.
- 영향: 승인 채널 영상의 종료 후 추천은 같은 채널로 좁힐 수 있지만, 플레이어 안에서 YouTube로 이동하는 링크와 실제 재생 정책을 완전히 통제하지는 못한다.

## 2026-10-09 — 검색은 제출 시 실행하고 아이 화면은 두 탭으로 구성한다

- 결정: 검색은 검색어 입력을 마친 후 검색 버튼을 눌렀을 때 실행한다. 아이 화면은 `검색`과 `승인 채널 영상` 두 탭을 기본 구조로 둔다.
- 근거: 사용자가 검색 호출을 아끼는 방식과 아이 화면의 두 가지 주요 이용 경로를 지정했다.
- 검토 후 채택하지 않은 대안: 입력 글자마다 자동 검색하거나 YouTube 홈·쇼츠 피드를 보여주는 방식.
- 영향: 검색 탭은 전체 검색 결과를 보여주고, 승인 채널 영상 탭은 해당 아이 프로필에 승인된 채널의 영상을 보여준다.

## 2026-10-09 — 부모 승인은 서비스 내부 채널 목록으로 관리한다

- 결정: 부모가 승인한 YouTube 채널을 아이 프로필의 서비스 내부 허용 목록에 저장한다. 승인과 동시에 아이의 실제 YouTube 계정에 구독을 추가하지 않는다.
- 근거: 사용자가 서비스 내부 승인 채널이면 충분하다고 답했다. 실제 YouTube 구독 추가는 별도 계정 권한이 필요하고, 아동 대상 API 클라이언트의 쓰기 동작에는 정책 제한이 있다.
- 검토 후 채택하지 않은 대안: 부모 승인과 실제 YouTube 계정 구독을 자동으로 묶는 방식.
- 영향: 기본 서비스는 자녀 YouTube 계정 연결 없이도 승인 채널 영상 목록을 제공한다. 기존 구독 목록 읽기 연동은 별개 후속 기능으로 남긴다.

## 2026-10-09 — 북마크는 승인 채널 목록을 뜻한다

- 결정: 이 서비스의 북마크는 아이 프로필별로 부모가 승인한 YouTube 채널 목록과 그 채널의 영상 목록이다. 영상 한 편을 별도로 저장하는 북마크 기능은 범위에서 제외한다.
- 근거: 사용자가 승인 채널 영상 탭 자체가 북마크 경험이라고 명확히 했다.
- 검토 후 채택하지 않은 대안: 승인 채널 목록과 별도로 영상 단위 저장 목록을 운영하는 방식.
- 영향: 아이 화면은 검색과 승인 채널 영상의 두 탭으로 충분하며, 부모의 채널 승인·취소가 목록 내용을 결정한다.

## 2026-10-09 — 재생은 승인 채널 영상에만 제공하고 미승인 결과는 채널 추가 요청으로 받는다

- 결정: 검색 탭은 전체 검색 결과를 유지한다. 승인 채널 영상 카드만 재생 표시를 두고 누르면 즉시 재생한다. 미승인 채널 영상 카드에는 재생 버튼·재생 유도 표시를 두지 않고 플레이어도 만들지 않으며, 카드 동작은 "채널 추가 요청"이다. 아이 화면에 "부모님이 고른 채널만 재생되며 YouTube 제한이 아닌 가족 설정"이라는 안내를 상시 표시한다. 승인 모드 해제 시 동작은 기존과 같다.
- 근거: YouTube 개발자 정책 III.F.3.b와 해설은 재생 버튼 외 행동을 시청 조건으로 요구하는 관문을 금지한다. 서비스가 재생을 제공하는 범위를 정하는 기능 제한은 III.C.6·C.7(핵심 목적, 제한 이유 안내)로 설명할 수 있다. 상세는 `docs/01_youtube-policy-review.md`.
- 검토 후 채택하지 않은 대안: 미승인 영상을 재생 가능한 형태로 보여주고 선택 시 재생 대신 승인 요청을 띄우는 기존 흐름(위반 위험 높음). 검색을 승인 채널 내 검색과 채널 찾기로 분리하는 방식(전체 검색 상실·할당량 부담).
- 영향: 검색 결과 카드가 승인 상태에 따라 두 형태로 나뉜다. 승인 요청은 "영상 재생 요청"이 아니라 "채널 추가 요청"이며, 요청 계기가 된 영상은 부모 판단용 참고 정보로 함께 전달한다. 정책 문서에 보호자 통제를 직접 다룬 조항은 없으므로 명시적 허용이 아니라 해석상 방어 가능한 설계다.

## 2026-10-09 — YouTube API Compliance Audit은 신청하지 않는다

- 결정: 정책 해석을 Compliance Audit으로 공식 확인받지 않고 가족 전용 소규모 서비스로 운영한다.
- 근거: 사용자 선택.
- 검토 후 채택하지 않은 대안: 화면 흐름 확정 후 Audit 신청.
- 영향: 위반 판정 시 API 키 회수·할당량 축소 위험을 감수한다. 서비스는 가족 외부에 공개하지 않는 것을 전제로 둔다. 정책 개정 여부는 출시 전 재확인한다.

## 2026-10-09 — 첫 버전 계정·승인·알림·화면 규칙

- 결정:
  - 가족 계정 추가: 부모가 구성원의 Google 이메일과 권한(부모/아이)을 사전 등록한다. 등록된 이메일로 로그인하면 연결된다. 초대 링크는 쓰지 않는다.
  - 아이 계정과 프로필: 아이 계정 1개에 아이 프로필 1개를 연결한다. 아이는 로그인하면 자기 프로필로 바로 들어가며 프로필 선택 화면은 없다.
  - 승인 범위: 채널 승인은 아이 프로필별로 적용한다. 가족 공통 승인은 두지 않는다.
  - 거절·재요청: 거절된 채널은 아이가 다시 요청할 수 없고 카드에 "부모님이 거절한 채널"로 표시한다. 부모가 거절 목록에서 해제하면 다시 요청할 수 있다.
  - 알림: 승인 대기함을 원본으로 두고, 알림은 PWA 웹 푸시만 사용한다. 이메일 알림은 두지 않는다.

- 근거: 사용자 결정(1번 A안). YouTube 검색 API에는 제목·채널명만 골라 찾는 옵션이 없어, 대상(영상/채널)을 나눠 찾는 방식이 가장 정확하다. 요청에는 계기 영상이 필요하므로 채널 화면에서 영상을 고르게 한다.
- 검토 후 채택하지 않은 대안: 받은 영상 결과 안에서 제목/채널명으로 거르기(B안, 결과 50개 안에서만 찾을 수 있음).
- 영향: 채널 화면을 열 때마다 일반 할당량 약 2단위(재생목록 1 + 영상 정보 1)를 쓰고 영상 목록은 저장하지 않는다. 채널 정보는 공유 캐시에 저장된다(부모 채널 검색과 같음). 요청 시트와 결과 카드를 검색 탭·채널 화면 공용 컴포넌트(`web/src/app/kid/request-sheet.tsx`)로 분리했다.

## 2026-10-11 — 쇼츠 목록이 없는 채널은 빈 목록으로 처리한다 (버그 수정)

- 결정: 채널 영상 갱신·이전 영상 더 보기에서 재생목록이 없다는 응답(404 playlistNotFound)은 오류가 아니라 빈 목록으로 본다.
- 근거: 자동 갱신 상태를 점검하다 발견. 쇼츠가 없는 채널(오색나물·베타갤럭틱·MARETU 등)은 쇼츠 목록(UUSH…)이 404라 갱신이 중간에 실패해 '마지막 갱신 시각'이 기록되지 않았다. 일반 영상은 저장됐지만, 접속할 때마다 갱신을 다시 시도해 할당량을 낭비하고 새 영상 추가도 실패할 수 있었다.
- 검토 후 채택하지 않은 대안: 쇼츠 목록 존재 여부를 미리 확인하는 추가 호출.
- 영향: 다음 갱신부터 해당 채널도 정상 기록된다.

## 2026-10-11 — 채널 영상 탭 목록은 나눠 그린다

- 검토 후 채택하지 않은 대안: '더 보기' 버튼으로 나눠 보기(누르는 수고), 가상 스크롤 라이브러리 도입.
